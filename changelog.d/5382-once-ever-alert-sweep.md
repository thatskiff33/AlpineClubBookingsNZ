- **A once-only admin alert is no longer lost when the database fails at the wrong moment (#5255).**
  Some admin alerts are sent once ever: the app notes that the alert has gone, then sends it. Since v0.14.0 a failed note is taken back so the next run tries again, but two rarer cases still lost the alert for good: the database stayed down for both attempts to take the note back, or it saved the note only after the app had taken it back. A new first task of the 15-minute payments job, **Once-ever admin alert sweep** on the cron health page, now finds a note that has had no email behind it for 15 minutes and takes it back, so the alert is sent on the next run. An alert is never sent twice because of it: the alert's email record and the note are written together, so whichever comes first wins.
  Five alerts that are raised only at the moment something goes wrong (a capacity-race refund short of the charge, a refund whose recovery job could not be closed, a card refund past its charge, a booking change paid twice, and a Xero success after an officer resolved the job) are now stored so the same job re-sends them until an officer has them, for up to seven days. Before, the error log was their only record if the first send failed.
  Two rarer cases remain and are being fixed separately: an alert raised while the database refuses every write is still only logged (#5297), and an email the app recorded as queued but never handed to the mail server is never sent (#5298).
