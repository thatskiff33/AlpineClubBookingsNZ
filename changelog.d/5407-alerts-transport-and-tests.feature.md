- **The mail transport now has its own timeouts, as three optional settings (#5407).**
  Every email provider (AWS SES, an SMTP relay or a capture mailbox) now gives up on a stuck send instead of waiting on the mail library's long defaults: 30 seconds for the whole connection setup, covering the lookup, the connect, the server's greeting and the secure upgrade together (`EMAIL_SMTP_CONNECTION_TIMEOUT_MS`, default `30000`, down from two minutes), at most 15 seconds of that for the greeting (`EMAIL_SMTP_GREETING_TIMEOUT_MS`, default `15000`, which only matters when lower than the setup budget) and 2 minutes of silence on an open connection (`EMAIL_SMTP_SOCKET_TIMEOUT_MS`, default `120000`, down from ten minutes). Each accepts `1000` to `600000` milliseconds; any other value is ignored with a warning in the setup readiness checks and the default is used, and a greeting value above the setup budget is warned about because it has no effect. A healthy mail server answers well inside these limits, so nothing changes for a club whose mail already works, and a send that times out is handled exactly as any other failed send.
- **The repeated Xero failure alert's limit now holds when the club has saved its own subject for it (#5407).**
  The alert goes out at most once a day for the same failing Xero item. That limit used to find the earlier alert by its built-in subject, so a club that had saved its own subject line for the alert in Admin, Email Messages was sent it on every further failure. It now keeps its own record of each alert raised, so the limit holds whatever the subject says. Clubs using the built-in subject see no change.
