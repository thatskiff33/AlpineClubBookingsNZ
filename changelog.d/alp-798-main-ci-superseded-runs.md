- **Merges to `main` no longer queue a full set of CI runs each (#5356).**
  When several pull requests merge close together, a newer merge now replaces `main`'s queued runs of CI, E2E, Money coverage and Docs link check instead of waiting behind them. A run that has started still finishes, and the newest `main` commit gets its full set (unless someone re-runs an older one at the same time), so open pull requests stop waiting behind `main`'s backlog. The checks that only run on `main` now judge each push from the last `main` commit whose run reached them, so a merge whose run was dropped is still checked. An intermediate commit whose run was replaced has no published images; `release:cut publish` already refuses to tag one, and its default, the newest `main` commit, normally has a successful run; `release:cut publish` refuses otherwise. CONTRIBUTING.md explains how to find which merge broke `main` by re-running the replaced runs. CI only; no behaviour changes for clubs.
