# Money-path sweep of the pre-review window (May–June 2026)

**Audience: maintainer, treasurer, future agent.** Issue #3341, item 2. Swept 26 September 2026.

## Why this sweep exists

Between 1 May and 30 June 2026, 459 pull requests merged into this repository, of which about 455 carried no review comment (the issue counts four June PRs with one). One of them, PR #543, retired a payment instrument without re-homing the debt it represented. Four months later that cost two members $135 (#3340). This sweep went back over the same cohort looking for the next one.

## What was swept, and how

- **Population:** every pull request merged 1 May – 30 June 2026 (459). A PR was in the **money-path subset** if it changed a non-test file under `src/` or `prisma/` whose path names payment, refund, credit, settlement, Stripe, Xero, pricing, price, fee, invoice, money, charge, cents, modification, modify, cancel, additional, ledger or reconcile. `modify` was added during the sweep: ten PRs (#318, #327, #437, #467, #469, #522, #527, #544, #554, #718) qualify only through `modify` paths. **171 PRs** were in the subset; none was hidden by the 100-files-per-PR listing cap.
- **Coverage:** all 171 were read, from their diffs, by four reviewers in parallel. None was skipped and none was unreadable. The 288 PRs outside the subset were not read — among them #853 (guest removal, `src/app/api/bookings/[id]/guests/[guestId]/route.ts`), whose path names none of the words.
- **The defect class:** (A) an instrument (payment intent, transaction row, invoice, credit note, manual payment, credit) cancelled, voided, superseded, expired or replaced without the money it represented being carried onto a surviving instrument; (B) a per-change delta used where an outstanding balance is meant. A money assertion disabled by a mock was also noted.
- **Method:** each suspect was checked against current `main` and refuted if a later change had fixed it or the path was unreachable. Only suspicions that survived refutation became findings. Each finding was then re-verified by an independent adversarial pass before it was filed.
- **Positive control:** PR #543 came out in class A, as it must.
- **Limits:** the sweep read the money files in each diff. Test files were only partly read, so the mock shape is covered structurally by `INV-OPS-015`'s census rather than by this document. Xero-side behaviour was inferred from code, not exercised against Xero.

Six new live defects were filed, in five issues (#3639 holds two), as children of wave #3634 and fixed there:

- **#3638** (PR #827): switching a card booking to internet banking can collect it twice, silently.
- **#3639** (PRs #235, #668): a cancelled booking's money is re-decided later without asking what the cancellation settled (a delayed Stripe notice; the repair tool).
- **#3640** (PRs #271, #626): a card refund after an account-credit settlement is lost from the refunded total.
- **#3641** (PR #531): a change's waiting Xero invoice is retired while the member can still pay it.
- **#3642** (PR #829): a group's internet-banking invoice is not rebound when the settlement changes.

The refuted suspects read as a list of this class's past escapes:

- #543 itself, fixed by #3364.
- #684, which carried the #3340 shape into the add-guests route until #3364 closed that door too.
- #257 and #578, which carried it through a rewrite and a move.
- #357, which clears a local record but loses no money.
- #239, #440, #556, #620, #669, #672, #735, #801 and #807, each fixed by a later PR named in its row.
