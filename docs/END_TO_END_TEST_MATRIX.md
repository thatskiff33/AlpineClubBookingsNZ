# End To End Test Matrix

This first-pass matrix links personas, journeys, risks, test types, and likely
validation commands. Use it to plan focused issues and avoid claiming coverage
that does not exist yet.

Public CMS authoritative-block coverage must exercise enabled/disabled states,
home/code-backed/catch-all/404 parity, global and lodge variants, current-date
fee boundaries, divergent card/credit cancellation terms, invalid lodges,
sanitisation, and authority-write cache invalidation. Signed-out output must
contain no ids, provider codes, internal settings, or legacy entrance fallback.

The rows marked "Playwright E2E" below now have automated browser coverage in
`e2e/` run against the staging compose stack — see
[`E2E_PLAYWRIGHT.md`](E2E_PLAYWRIGHT.md). This spans the Critical booking,
two-factor, Stripe, and cancellation-with-refund rows plus the High
role-boundary, role-management, waitlist, internet-banking, bed-allocation,
partner-shared double-bed, and membership-application rows. The Stripe payment
specs skip unless genuine Stripe
test-mode keys are configured, and they cover **only test-mode payment success
and decline**. The cancellation-with-refund spec
(`e2e/booking-cancel-refund.spec.ts`) covers the cancel → **account-credit**
money outcome; **card-refund** (a real Stripe refund), saved-card, and
member-credit paths still have no browser coverage (Vitest/service only). The
deliberate, ratified browser-coverage gaps (cron-driven waitlist offer/expiry,
webhook signature classes) are listed in `E2E_PLAYWRIGHT.md`. Email-code 2FA is
covered by `e2e/two-factor-email.spec.ts`.

Concurrency-under-load coverage (the "stable at 100+ concurrent users"
target) lives outside this matrix in the k6 harness under `load/` — public
browse, login, member-dashboard reads, and the booking-hold contention
stampede over the per-lodge advisory lock. See
[`LOAD_TESTING.md`](LOAD_TESTING.md); runs are owner-gated and target only
the throwaway staging stack.

## Custodian occupancy (#2286) and whole-lodge hold occupancy (#2317): unit-only, deliberately

The two custodian rows above are validated by unit and integration suites, not
by Playwright, and that is a decision rather than a gap.

The behaviour that matters is **arithmetic and refusal**: which bed-nights leave
the pools, which write paths refuse, and which names the display serialiser
withholds. Every one of those is a pure function of a `HutLeaderAssignment` row
plus a date, and each is asserted directly — including the mutation-sensitive
cases (a reconcile leaving a held bed empty, a hold created *between* the plan
and the write, a range refusing only the held nights). A browser cannot observe
any of it more sharply than the unit assertions do.

The minor-suppression contract in particular is asserted at the serialiser,
which is the only place it can be enforced: the payload is what leaves the
building, so `custodian-display.test.ts` asserts the built payload contains no
minor's name at `FULL_NAME` granularity. Driving the same case through
`e2e/lobby-display.spec.ts` would need a bed-holding assignment for a
minor-age member seeded into the staging stack, and would then assert on
rendered text that the serialiser had already been proven never to produce —
weaker evidence at a much higher cost. If a future change moves any of that
decision into the template, this row must be revisited.

The **whole-lodge hold occupancy** row (#2317) is unit-only for the same reason
and one more. What has to hold is that two planners and the capacity engine
agree about which nights are taken, and that the occupancy carries no
attribution — a claim about the SHAPE of the planner's input, which a browser
cannot see at all. The suite proves it where it lives: the same booking fixture
is fed through a `where`-honouring database double to `getLodgeHeldNights` and
to the board, and their night sets are compared; the synthesised rows are
asserted to carry a null booking, a null guest and no age tier, and to name
nobody. The suite is mutation-verified — removing the capacity-holding
predicate, either planner's feed, either writer's re-check, any of the guards
that keep a held bed-night occupied when the booking sharing it is evicted, or
the filter that applies a displacement only when the re-checked payload still
claims the bed-night it frees, each fails a distinct test.
